## What it does (user-facing)

1. **Owned-trade marking** — trades the villager already sells (picked at an earlier
   level, or imported as legacy offers) show a green ✔ on the card, dimmed colors, and
   "(already on this villager)" in the tooltip. Still pickable (duplicates allowed on purpose).
2. **hidePickedTrades config** (default OFF) — removes owned cards from the picker
   entirely. Never filters below `picksRequired` so a level can always be filled.
3. **Default sort by type** — picker cards sort by result item id → enchant base name →
   level → pool order. Display-only; selection indices and network picks unchanged.

## Porting procedure per cluster

1. `git checkout backport/<ver>` then `git cherry-pick f505538`. Expect clean or
   near-clean picks within the 1.21.x line — these files barely differ across clusters.
2. Conflict hotspots if any:
   - `TradePickerScreen.mouseClicked` signature differs on older clusters
     (1.21.1-1.21.5 use `mouseClicked(double,double,int)`, not `MouseButtonEvent`) —
     the #7 diff doesn't touch it, but fuzzy context may collide.
   - `OpenPickerS2C` — keep `ownedKeys` LAST in the codec on every cluster.
3. Version bump suffix must match the cluster (`1.3.1+mc1.21.1`, `1.3.1+mc1.21.4`, ...).
4. Gate: `./gradlew :fabric:build -x test` then `./gradlew :fabric:runGametest` —
   all required tests green (17 on 1.21.9; count differs per cluster).
5. NeoForge clusters: same common-code change applies; rebuild `:neoforge`, run
   `:neoforge:runGameTest`. Lang file lives in the fabric resources on backport branches —
   check whether the NeoForge module has its own copy of `en_us.json` and mirror the two keys.

## Design decisions (don't re-litigate when porting)

- Owned detection = pick-key match (book/gear/arrow keys are merchant-level independent)
  **plus** legacy-offer result-stack match. Flat `listing/<level>/<idx>` keys never collide
  across levels — that's fine, the pain point was books/gear.
- Owned cards stay pickable when only marked: a player may WANT a second copy of a trade
  for more stock. The server never rejects owned picks.
- Sort is client-side only. Server pool order still drives auto-pick fast path and
  validation. Roman-numeral parse handles I-V plus arabic fallback.
- `maxBookPicks` sent to the client is computed from the FILTERED list, and submit-side
  validation recomputes it from the same filtered list — do not "simplify" either side to
  the full pool or vanillaBookLimits+hidePickedTrades combos can reject legit submits.
